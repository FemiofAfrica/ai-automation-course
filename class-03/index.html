01Recap and Readiness Gate

Two weeks ago you learned the pipeline. Last week you built a Brand Context Vault. This week that vault becomes the memory of a running system. But first we confirm the vault actually exists and is populated. A harness with an empty vault produces confident nonsense.

Femi's note from last class

We ended around setting up your vault, and I gave you a Claude Code prompt to create the vault and start adding information. If that prompt did not finish, this is where we find out and fix it. We do not re-teach Class 2. We verify, repair, and move on.

The gate has four steps. All four must pass.

1

Confirm Claude Code can open the vault

Open a terminal in your vault folder and run claude. Ask it to list the files it can see. If it sees your notes, the path is correct. If it says the folder is empty, you are in the wrong directory.

3

Run the repair prompt if anything is missing

This prompt tells Claude Code to create only what is missing, without touching what you have. It is safe to run even if the vault is already complete.

Read the vault I have open. Check for these six notes and create

   index instead of creating a duplicate.

  different name, link it from index and skip creation.

Context test, the real proof

With Claude Code open in the vault, ask it one question only your vault can answer. Example:

context-test.md
Name one word our brand never uses, and tell me which note that
rule lives in. Then summarise, in your own words, who our primary
buyer persona is and the single objection that blocks them.

Pass looks like: it quotes your actual banned word and your actual persona, citing the note names. Fail looks like: generic marketing advice, or "I don't have that information." If it fails, your notes are not where Claude Code is looking, or they are empty.

02The Harness Architecture

A harness is the software that wraps a model with everything it needs to do a job without you in the room. Claude Code is the harness. Your vault is its memory. Composio is its hands on Meta. A skill is its written procedure. The schedule is its alarm clock. Learn these nine layers now, because when something breaks next week, you will diagnose it by layer.

The one analogy: your marketing deputy

Picture a deputy you hired and seated in your office. The brain is their judgment. The instructions are the desk card that says "always check the banned list before publishing." The vault is the filing cabinet of everything they know about your brand. The skills are the procedure binders: "here is exactly how we write the Monday report." The tools are the phone to Instagram and Facebook. The permissions are the keycard that opens the cabinet but not the safe. The memory is the notebook where they record what ran and what broke. The schedule is the alarm clock set for Monday 8am. The delivery is the courier who drops the finished report on your desk. Nine layers, one employee.

1 Brain

Model

Claude does the reasoning. You pick the model in Claude Code. For a report that reads files and writes prose, Sonnet class is the right daily driver. You do not change this per run.

2 Instructions

CLAUDE.md

The standing rules for this project, written once in a file called CLAUDE.md. "Treat the vault as source of truth. Never invent metrics. Save reports to reports/weekly/." Loads every session.

3 Context

Vault

Your Class 2 notes. The skill tells Claude which notes to read for a report, so it loads only the slice it needs, not the whole vault.

4 Skills

Procedure binder

A folder with a SKILL.md that says how to build the weekly report. Reusable, version controlled, and shareable. This is the heart of the build.

5 Tools

Composio MCP

Composio connects Claude Code to Instagram Business and your Facebook Page through managed OAuth. No API keys in your files. The tools arrive as Meta data calls.

6 Permissions

Approval boundaries

Claude Code asks before risky actions. The skill pre-approves the safe ones (read vault, write report) and leaves destructive ones (post to social) for you to approve.

7 Memory

State

The harness writes a run log: what it pulled, what it found, whether delivery succeeded. Next week's run can see last week's, so it notices trends and failures.

8 Trigger

Schedule

Claude Code's own scheduler is session scoped and expires in seven days, so for a weekly job we use your laptop's scheduler (cron on Mac, Task Scheduler on Windows). Laptop must be on and online.

9 Delivery

Output

The report is written as a dated Markdown file into reports/weekly/, then emailed to you through a connected Composio email toolkit if available, or flagged for you to collect.

03Install the Instruction File and the Skill

Two files turn a chat tool into a system. CLAUDE.md holds the standing rules. The skill holds the procedure. Both live in or next to your vault so they travel with it.

Step A: CLAUDE.md at the vault root

Create a file called CLAUDE.md in your vault folder. This is the instruction layer. Keep it short and imperative.

CLAUDE.md - project instructions, lives at the vault root
# Project: [Brand] Marketing Harness

You are the marketing analyst for [Brand]. Your brand context vault is
the folder this file lives in. Treat the vault as the source of truth.
Your training data is not a source of truth about this brand.

Rules:
- Before any report, read index.md, then brand-voice-guide.md, then the
  relevant persona, then do-not-says.md.
- Never invent a metric. If Meta returns no data for a window, write
  "no data" for that metric. Real numbers only.
- Save every weekly report to reports/weekly/ with the date in the filename.
- Append a one line status to reports/weekly/run-log.md after every run:
  date, what was pulled, delivery result or error.
- For any price, claim, or capability, use product-facts.md only.

  that specific action in the session.

Create .claude/skills/weekly-marketing-insights/SKILL.md. The path is exact: a folder .claude/skills/, then a folder named after the skill, then SKILL.md inside it. 04Connect Composio to Instagram and Facebook

Composio is the bridge that lets Claude Code call Meta without you writing API code or storing tokens. You install the plugin, then connect each app with a real OAuth approval. This is the one step that must happen on the student's machine with the student's account, so we set it up live and verify before building anything on top of it.

Account prerequisites, read before connecting

Instagram must be a Business or Creator account linked to a Facebook Page. A personal Instagram profile will not return insights. The Facebook side must be a Page, not a personal profile. Both should sit under the same Meta Business Manager. If either is wrong, Composio connects but returns empty data, and you will waste the rest of the class guessing why.

1

Install the Composio plugin in Claude Code

Run these two commands inside Claude Code. The first adds Composio's marketplace, the second installs the plugin. Claude Code may ask you to reload plugins.

claude-code commands
/plugin marketplace add ComposioHQ/composio-plugin-cc
/plugin install composio@composio
2

Connect Instagram Business

In Claude Code, run the connect command for instagram. It opens an OAuth link in your browser. You approve it personally. Claude Code confirms the connection.

claude-code command
/composio-connect instagram
3

Connect your Facebook Page

Same pattern for facebook. Approve the Page you want reported on, not your personal profile.

claude-code command
/composio-connect facebook
4

Verify before you build on it

Ask Claude Code to confirm the connections and pull one real fact. If it returns a follower count or account name, the bridge works. This is the verification call the brief requires, done before any report is written.

verification prompt
List my connected Instagram Business account and its follower
count, and my connected Facebook Page and its page likes. Tell me
which toolkit returned data and which returned "no connected account".
Secret handling, the rule that is not negotiable

Composio manages the OAuth tokens for you. They are never in your vault, your CLAUDE.md, your skill, your screenshots, or this course repo. If any step asks you to paste a token into a file, stop. That is not how this works. Least privilege applies: you connected only instagram and facebook. Do not connect every app Composio offers "just in case."

When one toolkit connects and the other does not

This is the most common failure and it is easy. If verification says Instagram returned data but Facebook returned "no connected account", run only the facebook connect again. The two connections are independent. Do not reinstall the plugin. Do not rebuild the skill. Connect the missing one and re-verify.

05Pull Raw Data and Find the Missing Metrics

Before any analysis, look at what actually came back. Meta suppresses and deprecates metrics, and a report that quietly drops a number is worse than one that says "no data." Train your eye on the gaps now.

The quirks that will bite you, from the local Composio Meta reference

These are the documented behaviours of the Meta toolkits through Composio. The tool names below are the canonical Composio slugs; in the Claude Code plugin they appear under the composio MCP namespace, so confirm exact names with /composio list and adapt if yours differ.

  • Instagram tools take integer unix timestamps for since/until. Facebook insights take string dates like -7 days or now. Mix them up and you get a 400.
  • Metrics are silently omitted when there is no data in the window. The response tells you which were requested versus returned. Report what is present, say "no data" for the rest.
  • follower_count is suppressed under 100 followers. Use the user info call for followers_count at any size.
  • Facebook per post engagement (reactions, comments, shares) comes from the post object, not from post insights. The old post impression metrics were deprecated in November 2025 and return nothing.
  • Wrong argument name returns a 400 naming the exact field you missed. Copy the name from the reference, do not guess.

Exercise 5 Inspect Raw Data, Name the Gaps

07Schedule a Test Run and Verify Delivery

The finish line is not "a report can be generated." It is "a report arrives every week without you." Claude Code's own scheduler is session scoped and expires in seven days, so for a durable weekly job we use your laptop's scheduler. We test with a run a few minutes out, confirm delivery, then set the real Monday cadence.

Why not Claude Code's built in scheduler for production

Claude Code's scheduled tasks live inside the current session and stop when you start a new one. The docs state they are restored on resume only if unexpired, with a seven day expiry. For a weekly report that must survive restarts and weekends, that is not durable enough. The reliable route on a student laptop is the operating system scheduler: cron on macOS and Linux, Task Scheduler on Windows. Honest caveat: laptop based automation only runs when the machine is on and connected. State that plainly to the student.

The safe non-interactive run command

This launcher runs Claude Code headless: it prints the result and exits, pre-approving the safe tools so it does not stall. It assumes the vault is the current directory or the path is set. The skill name is passed as the prompt.

run-report.sh - macOS and Linux launcher
#!/usr/bin/env bash
# Run the weekly marketing report headless.
# Usage: ./run-report.sh
set -euo pipefail
cd "/path/to/your/brand-context-vault" || exit 1
claude -p "/weekly-marketing-insights" \
  --allowedTools "Read,Write,Edit,Glob,Grep,mcp__composio__INSTAGRAM_*,mcp__composio__FACEBOOK_*" \
  --add-dir "/path/to/your/brand-context-vault"

Replace the two /path/to/your/brand-context-vault strings with your real vault path. On Windows use the schtasks command in the starter pack instead of this script. The --allowedTools list must match the tools your skill uses, or the run will pause for approval.

Test schedule, a few minutes out

On macOS or Linux, add a temporary cron line that fires in about three minutes, then check reports/weekly/ and the run log. This proves the chain before you trust the weekly one.

test cron (macOS / Linux)
# Show current crontab, then add a test line 3 minutes out
crontab -l
( crontab -l; echo "$(date -v+3M +'%M %H * * *') /path/to/your/brand-context-vault/run-report.sh >> /path/to/your/brand-context-vault/reports/weekly/cron.out 2>&1" ) | crontab -
# After it fires, check:
ls -t /path/to/your/brand-context-vault/reports/weekly/
tail -n 20 /path/to/your/brand-context-vault/reports/weekly/cron.out
Delivery: the visible finish line

Default recommendation: email the report to your own address through a connected Composio email toolkit (Gmail, for example). If that connection is not set up, the fallback is honest: the report is written to the vault and the run log is flagged "not delivered." That fallback does not meet the full delivery acceptance criterion, so we name it clearly and the student connects email as the last live step. Do not invent the student's email address. Put it in the field below and in the scheduler, never in a committed file.

The email itself is supplied by the human at run time, from the connected email toolkit, and is never written into CLAUDE.md, the skill, the repo, or this handout.
