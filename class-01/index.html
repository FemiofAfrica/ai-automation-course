01The Mental Model: One Pipeline, Every Tool

Before vocabulary, get the architecture. Whether you type a question into ChatGPT, use Claude.ai, or run a fully autonomous agent — the same pipeline runs behind the scenes. The only difference is how many of the middle steps actually happen.

Every time you interact with AI — this pipeline runs. Understanding it means you can diagnose why an output is weak and know which lever to pull. That skill is the whole course.

The loop behind "autonomous"

An agent doesn't answer once and stop. It runs plan → act → observe → adjust until the job is done or it needs you. Each loop spends tokens — which is why an unconstrained agent can burn budget (we'll meet the money in Section 07). For now: autonomy = the pipeline repeating itself with feedback.

02The Vocabulary: Seven Words That Unlock Everything

Marketing execs get sold "AI" as one thing. It isn't. Seven words — and you can decode any vendor pitch, any tool, any article.

The brain

Model

A pattern-recognition machine trained on enormous amounts of data. It doesn't think — it predicts the next most likely word, image, or action.

Analogy: a brilliant new hire who has read the entire internet. Needs clear instructions. Knows nothing about your brand yet. Can hallucinate confidently.

The brain, bigger

LLM

Large Language Model = a text model scaled up enough to hold conversations and generate long-form content.

Key properties: context window (how much it can "see" at once), tokens (how it counts text), temperature (creativity vs. precision).

The waiter

API

Application Programming Interface — the structured way one tool asks another for data or actions. Pull.

"Go get data from this place." Your spreadsheet auto-syncing with your CRM, instead of copy-pasting between them.

The phone call

Webhook

A notification: "call me when something happens." Push.

New lead fills your form → a webhook tells your CRM instantly. Form → WhatsApp alert to sales. No polling, no delay.

The worker

Agent

An LLM with tools, memory, and autonomy. Given a goal, it works multi-step: searches, reads, drafts, decides.

Analogy: the intern after six months — knows your brand, works without hand-holding, tells you when something needs you.

The wrapper

Harness

The software that wraps a model with a chat interface, tools, memory, and delivery. A tool is not a model.

ChatGPT, Claude.ai, Copilot, Hermes — all harnesses. GPT and Claude are models. This distinction alone saves you from bad vendor math.

The plug

MCP

Model Context Protocol — the open standard (2026) that lets any AI assistant plug into your tools: Drive, CRM, databases. One plug instead of custom cables per pair.

Think "USB-C for AI connections." When a vendor says "we support MCP," it means their AI can reach your tools without a bespoke integration.

The single most useful distinction of the day

Model ≠ Tool. "ChatGPT" is not a model — it's a harness around models. When someone says "we use AI," ask: which model, and which harness? When results differ across tools, it's usually the harness (pipeline steps ②③④), not the brain.

03How Automation Actually Works

The vocabulary gives you the parts. Now see how they move. Every automation — whether it's n8n, Zapier, or a full agent — is the same three-part loop. Learn this and no automation will ever look like magic again.

1

Trigger — what starts it

Three kinds. Event (the webhook rings — a form filled, an email received). Schedule (the clock — every Monday 8am). Manual (you click "run now").

The first question to ask about any automation: what starts it, and how often does that happen?

2

Action — what it does

The work: fetch data, ask the model, update the CRM, send the email, post the content. One action or a chain of them.

This is where APIs (pull) and webhooks (push) get used — the waiter and the phone call from Section 02.

3

Check — how you know it worked

Logs, alerts, or an approval request. Rule: fail loudly, never silently. If something breaks, a human should hear about it — fast.

Good automation tells you when it fails. Bad automation hides it and lets you believe the work happened.

Cron jobs — the "set and forget" engine

When an automation runs on a schedule, the clock is the trigger. Tools call it a schedule trigger, a recurring task, or a cron job — same idea, different names. Cron is the classic engine, named after the Greek word for time (chronos). You ask once; the machine asks forever, on time.

⏰ Every Monday 08:00→ Check competitor blogs→ Draft briefing with the model→ Send to your Slack

Your first automation wins are almost always scheduled: Monday competitor briefing, weekly campaign report, daily lead digest. You don't need to know how to write a cron expression — you need to know that schedules exist and can run without you.

An automation that fails silently is worse than no automation

Wrong data, an expired key, a changed form, a model timeout — automations break quietly all the time. If nothing alerts you, you keep believing the work is done while the pipeline quietly stops. Design rule: if it fails, tell a human. If it touches anything public, add an approval step. A good employee escalates; a bad one hides it.

04Pitfalls — Before You Hit Them

⚠️ Hallucination is normal

Every model invents things confidently. Verify numbers, quotes, prices, and anything that would embarrass you if wrong.

⚠️ It forgets between chats

Most chat apps have no persistent memory. If context matters, paste it into the message. (Week 4 fixes this permanently.)

⚠️ Context windows are finite

A model can only "see" so much at once. Very long documents get truncated. Give it the relevant slice, not the whole file.

⚠️ Same prompt ≠ same output

Different models and harnesses give different results for the same prompt. That's the pipeline, not a bug. Judge the tool by its output on your task.

⚠️ Don't paste customer data

Never put customer PII, contracts, or internal financials into a public tool until you know its data policy. Test with anonymized examples.

⚠️ Automations die quietly

Schedules miss, keys expire, feeds change. Set alerts, check your logs weekly, and always know who gets told when it breaks. (Section 03 rule: fail loud.)

05The Habits That Transfer: Briefing AI Like a New Hire

The skills in this section work identically on ChatGPT, Claude, Gemini, Copilot — any harness, most models. This is what "replicable on any harness" means: you're not learning buttons, you're learning how to brief intelligence.

1. Give it a role, audience, and goal

"You are a senior marketing strategist. I run a fintech for SME owners in Lagos. Our goal is demo signups from serious founders." The model can't know your context unless you give it — that's pipeline step ② in action.

2. Ask for a shape

"Give me a table," "bullet points," "a draft," "3 options ranked." Structured requests get structured, usable output — instead of paragraphs you have to rework.

3. One job at a time

Don't ask for strategy + copy + channel plan + calendar in one message. Sequence it: strategy first, then copy, then distribution. Or ask for a plan first and approve before it executes.

4. Ask for the reasoning

When the output matters, add: "Explain why this headline works" or "Show your logic." You can't evaluate what you can't inspect. This is your quality-control handle.

The meta-habit: verify before you trust

Every model hallucinates — produces confident, plausible-sounding nonsense. Numbers, dates, quotes, prices, statistics: check them. Treat AI output like a sharp new hire's first draft: useful, never assumed correct. This habit alone will save you more embarrassment than any prompt skill.

prompt-template.txt — copy this shape into ANY tool
# The universal brief — fill in the brackets, works on every model
ROLE:     You are a [senior marketing strategist].
CONTEXT:  I run [a fintech for SME owners in Lagos].
           We just [launched a bookkeeping feature].
           Our audience is [founders who do their own accounts].
TASK:     Write [3 LinkedIn post options] announcing it.
FORMAT:   A table: [Hook | Body | CTA | Why it works].
CHECK:    Flag any claim not supported by what I told you.

Exercise 4 The Transfer Test

Proof that today's skills transfer: take one real task (e.g. "summarize this week's campaign email"), brief it using the template above, and run it on two different tools — the one on your phone and the one on your laptop, or two free tools.

Compare the outputs: Which is more usable? Which needed more context from you? You've just experienced pipeline steps ②③④ in real life — same prompt, different harness, different result.

Success: you can explain why the outputs differed, using the pipeline.

06The Four-Layer Stack: Where Your Tasks Belong

Not every marketing task needs an agent. Most tasks need the cheapest layer that works. The maturity curve: most teams start at Layer 1 and grow up as they earn the right.

1

Chat & Reasoning ChatGPT · Claude.ai · Gemini

Ad-hoc analysis, drafting, brainstorming, summarizing. You talk, it answers. No memory between sessions unless you paste context in.

Use for: drafting an email, summarizing a report, brainstorming campaign angles, writing the first version of anything.

2

Workflow Automation n8n · Zapier · Make

Connecting tools end-to-end with no code. "When X happens, do Y with Z." Uses the trigger → action → check loop from Section 03 — schedules, webhooks, and APIs.

Use for: form → CRM, sheet updates, scheduled reports, content posting, anything that repeats on a trigger.

3

Autonomous Agents Hermes · custom agents

An LLM with tools, memory, and persistence. It remembers your brand, loads your skills, and executes multi-step work toward a goal — running the plan → act → observe → adjust loop from Section 01.

Use for: "monitor competitors and brief me weekly," "track this campaign and flag anomalies," tasks that currently eat 2+ hours of your week.

4

Orchestration multi-agent systems

Several agents coordinating — one researches, one writes, one distributes, one reports. For workloads that outgrow a single agent.

Use when: your operation is big enough that specialized agents sharing one knowledge base beat one generalist. Weeks 3–4 get you ready for this.

The maturity question

Where is your org today? Most are Layer 1 with a sprinkle of Layer 2. That's fine. The goal of this course is to move you deliberately up the stack — task by task, not all at once. And some tasks should never be automated: anything where judgment, relationship, or legal risk lives. Automation is a tool, not a religion.

07The Money: Tokens & Cost

AI is not free, and "how much does it cost?" is a question you'll answer in a budget meeting. The good news: the economics are simple enough to hold in your head.

Subscriptions vs. API

Chat apps charge a flat monthly fee ($20–200) and hide usage behind it. APIs charge per token — pay for exactly what you use.

Budget questions are really billing-mode questions: "Is this a fixed subscription task or a pay-as-you-go task?"

Tokens: the currency

One token ≈ ¾ of an English word (1,000 tokens ≈ 750 words). Every request has input tokens (what you send: prompt + context) and output tokens (the answer). More context = more input tokens = higher cost.

Why bills spike

Re-sending the same big context on every run. Agents looping many steps. Using the biggest model for everything. Feeding the whole file when a slice would do.

Week 2's vault is a real cost lever — we'll teach you to slice context, not dump it.

Rate limits

Providers cap how many requests you can make per minute/hour. Free tiers are tight; paid tiers are looser. If your automation suddenly fails, this is usually why.

"It worked in the test but fails at scale" is almost always a rate limit, not a bug.

The budget rule

Use the cheapest layer that works. Chat for ad-hoc, workflow for repeats, agent for the 2-hour weekly tasks. Cheap model for bulk work (product descriptions), top model for strategy (positioning, high-stakes copy). And check the pricing page before you build — not after the first invoice.

09A Look Ahead: How Your AI Will Know Your Data

One preview before you go — because it's the bridge to Class 2 and it explains why the next weeks feel different.

Closed-book vs. open-book

Today, when you use a chat tool, the model answers from what it learned during training — closed-book. It doesn't actually know your brand, your last campaign, or your customers. That's why generic output happens.

RAG (Retrieval-Augmented Generation) is the open-book version: before answering, the model looks up the relevant documents from your own knowledge base. Your campaign retros, personas, voice guide. It answers from your real history instead of guessing — and hallucinations drop sharply.

❓ "What did we learn last quarter?"→ Agent reads the campaign retro from your vault→ Answers from actual results

That's exactly what Class 2 builds: the brand vault your AI will read from. Today's Readiness Map tells you what to put in it.
